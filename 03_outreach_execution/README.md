# VenturelyHub Outreach Approval & Execution Workflow (Phase 3)

## 1. Overview & Objective

The **VenturelyHub Outreach Approval & Execution** workflow (`03_outreach_execution/outreach_execution.json`) is the gated dispatch engine of the VenturelyHub Marketing & Sales Automation system.

Its sole purpose is to enforce strict human authorization and send explicitly approved email drafts generated by Phase 2 via Gmail, while maintaining an immutable execution and audit log in Google Sheets.

### Strict Governance & Boundaries
- **Absolute CRM Rule Compliance:** This workflow contains **zero** CRM integrations, **no** customer or deal databases, and does **not** manage a sales pipeline or lead stages. Output is logged exclusively to the unified `VenturelyHub` Google Spreadsheet (`Outreach Execution Outputs` tab on dispatch attempt, `System Events` tab on validation/authorization error).
- **No Autonomous / Unreviewed Sending:** Every single outbound dispatch mandates explicit human approval (`approval_status: "APPROVED"`). Drafts with `PENDING_REVIEW`, `REJECTED`, or missing approval fields are hard-rejected.
- **Deterministic Sending (Zero AI Rewriting):** The message body and subject approved by the human reviewer are dispatched verbatim. No LLM (neither Gemini nor Qwen3) is invoked at send time, eliminating hallucination risks during dispatch.
- **Cryptographic Approval Fingerprinting:** Every approval decision carries an `approved_message_hash` calculated over `recipient_email`, `subject`, and `body` using a deterministic 64-bit FNV-1a hash (`h_<hex>`). If any content or recipient field is modified after approval, the workflow detects the mismatch (`APPROVAL_CONTENT_MISMATCH`) and aborts dispatch.
- **Duplicate Send Prevention (Replay Protection):** Every execution generates a composite `send_key` (`md5(recipient_email + "::" + subject + "::" + source_execution_id)`). Already-sent keys are tracked, preventing duplicate outreach to the same recipient for the same campaign.
- **Safe Test Mode:** In development and testing mode (`test_mode: true`), outbound email dispatch is strictly restricted to authorized safe test addresses (`srisaikirantambalkar@gmail.com`). Attempts to send to arbitrary prospect domains are intercepted with `UNAUTHORIZED_TEST_RECIPIENT`.
- **Single-Item Execution:** Dispatches exactly one email per execution. Batch looping or bulk sending is strictly prohibited.
- **Non-Blocking Fault Isolation:** Google Sheets logging nodes are configured with `onError: continueRegularOutput`.

## 3. Workflow Architecture & Pipeline Sequence

```
HUMAN APPROVAL PAYLOAD (POST /webhook/outreach-execution)
      ↓
[TRIGGER_ApprovalRequest] (Webhook POST /webhook/outreach-execution)
      ↓
[VALIDATE_ApprovalRequest] (Validates approval_status == "APPROVED", claims_validation, email format, test recipient, and verifies approved_message_hash)
      ↓
[ROUTE_Validation] (If: isValid === true)
      ├── FALSE → [FORMAT_ErrorOutput] (Structures validation error and event metadata)
      │                ↓
      │           [GOOGLE_SHEETS_Append_SystemEvent] (Appends rejection record to 'System Events' tab)
      │                ↓
      │           [RETURN_ErrorOutput] (Returns structured error JSON to caller)
      ↓ TRUE
[CHECK_AlreadySent] (Evaluates send_key idempotency cache)
      ↓
[ROUTE_DuplicateCheck] (If: alreadySent === false)
      ├── FALSE (Duplicate) → [FORMAT_DuplicateError]
      │                             ↓
      │                        [GOOGLE_SHEETS_Append_SystemEvent]
      │                             ↓
      │                        [RETURN_ErrorOutput]
      ↓ TRUE (New Send)
[GMAIL_Send] (Dispatches email via Gmail node; onError: continueRegularOutput catches unconfigured credentials or API limits)
      ↓
[BUILD_SuccessAudit] (Formats execution record: execution_id, message_id, send_status, delivery timestamps)
      ↓
[GOOGLE_SHEETS_Append_Outreach] (Appends record to 'Outreach Execution Outputs' tab)
      ↓
[RETURN_Sent] (Returns final execution status JSON to caller)
```

## 4. Input Specification

The workflow accepts POST requests at `/webhook/outreach-execution` with the following schema:

```json
{
  "approval_status": "APPROVED",
  "approved_by": "SriSaiKiran (Human Reviewer)",
  "approved_at": "2026-10-02T00:00:00Z",
  "approved_message_hash": "h_ed4560c3374f7d44",
  "recipient_email": "srisaikirantambalkar@gmail.com",
  "recipient_name": "SriSaiKiran",
  "organization_name": "KiteMetrics AI",
  "subject": "Opportunity to Accelerate KiteMetrics AI Product Development",
  "body": "Hi SriSaiKiran,\n\nFollowing up on our technology acceleration discussion.\n\nBest,\nVenturelyHub",
  "claims_validation_status": "VERIFIED",
  "personalization_angle": "Startup engineering support",
  "recommended_offer": "Startup Product Acceleration Program",
  "source_execution_id": "EXEC-P2-20261001-9827",
  "test_mode": true,
  "test_fixture": true,
  "safe_test_recipient": "srisaikirantambalkar@gmail.com"
}
```

### Validation Rules
1. `approval_status` MUST strictly equal `"APPROVED"`. If `"PENDING_REVIEW"`, returns `UNAPPROVED_DRAFT`. If `"REJECTED"`, returns `APPROVAL_REJECTED`.
2. `claims_validation_status` MUST strictly equal `"VERIFIED"`. If `"FAILED"` or unverified, returns `CLAIMS_UNVERIFIED`.
3. `recipient_email` MUST be present, RFC-compliant, and free of header injection characters (`\r`, `\n`).
4. If `test_mode == true`, `recipient_email` MUST match `safe_test_recipient` (defaults to `srisaikirantambalkar@gmail.com`). Otherwise returns `UNAUTHORIZED_TEST_RECIPIENT`.
5. `approved_message_hash` must match the deterministic hash of the payload:
   $$\text{HashInput} = \text{recipient\_email} \parallel \text{"::"} \parallel \text{subject} \parallel \text{"::"} \parallel \text{body}$$
   If mismatched, returns `APPROVAL_CONTENT_MISMATCH`.

| Column | Type | Description |
| :--- | :--- | :--- |
| `execution_id` | String | Unique execution identifier (e.g. `EXEC-P3-20261001-9804`) |
| `created_at` | ISO Timestamp | Execution creation timestamp |
| `workflow_name` | String | Fixed: `VenturelyHub Outreach Approval & Execution` |
| `phase` | String | Fixed: `Phase 3 - Outreach Execution` |
| `status` | String | `SUCCESS` or `FAILED` |
| `test_fixture` | Boolean | True if triggered from synthetic fixture or test mode |
| `recipient_identifier` | String | Recipient email address |
| `channel` | String | Fixed: `GMAIL` |
| `message_id` | String | Gmail provider message ID or fallback ID |
| `sent_at` | ISO Timestamp | Timestamp when send operation executed |
| `raw_output_json` | JSON String | Complete execution audit payload |

Appends one row for every failed validation gate, rejection, duplicate block, or system exception:

| Column | Type | Description |
| :--- | :--- | :--- |
| `event_id` | String | Unique event identifier (e.g. `EVT-P3-20261001-4487`) |
| `created_at` | ISO Timestamp | Timestamp of event occurrence |
| `workflow_name` | String | Fixed: `VenturelyHub Outreach Approval & Execution` |
| `phase` | String | Fixed: `Phase 3 - Outreach Execution` |
| `event_type` | String | Rejection error code (e.g. `UNAPPROVED_DRAFT`, `APPROVAL_CONTENT_MISMATCH`, `ALREADY_SENT`) |

| `test_fixture` | Boolean | Test fixture flag |
| `message` | String | Human-readable explanation of rejection |

## 6. Execution Lifecycle & States

```
[Phase 2 Draft Package] (approval_status: PENDING_REVIEW)
         │
         ├─► [Human Decision: REJECTED] ──► Blocked (APPROVAL_REJECTED) ──► Logged to System Events
         │
         └─► [Human Decision: APPROVED] ──► Generate approved_message_hash
                   │
                   ├── Payload tampered after approval? ──► Blocked (APPROVAL_CONTENT_MISMATCH)
                   ├── Claims unverified? ──────────────► Blocked (CLAIMS_UNVERIFIED)
                   ├── Non-test email in test mode? ─────► Blocked (UNAUTHORIZED_TEST_RECIPIENT)
                   ├── Already sent before? ─────────────► Blocked (ALREADY_SENT)
                   │
                   └─► Passed all gates
                             │
                             ├─► Gmail Dispatch
                             │        │
                             │        ├── Success ──► status: SUCCESS
                             │        └── Provider / Credential Error ──► status: FAILED (Non-blocking)
                             │
                             └─► Logged to Outreach Execution Outputs
```
